# PCB quality gates: pedal-by-wire dual bridge

Status: **proposed release contract, not a fabrication approval**. This document ports lessons, not balloon circuitry. Scope is the 36–58.4 V bus and two motor/generator bridges. Tooling audit evidence and exact source revision: [tooling-audit-report.md](tooling-audit-report.md).

## Evidence contract

Each gate records input SHA-256 (schematic, board, project rules, libraries, BOM, models), tool/version, command, return code, report, verdict and reviewer. Verdicts are PASS / FAIL / NOT RUN; missing tools, missing or stale reports and parse failures never become zero defects. Run in a fresh output directory. Never overwrite or reroute the artifact being graded. Refill a copy explicitly, record before/after hashes and grade that exact release candidate. No waiver by message substring: bind each justified exception to object/net, rule, reason and reviewer. Re-run affected gates after any change.

## Actionable checklist

All boxes remain open until project-specific evidence exists.

- [ ] **G0 — requirements and authority:** nominate one schematic/PCB/BOM set; freeze bus minimum, 58.4 V maximum normal charge plus tolerance, transient envelope, motor speed/back-EMF, phase current RMS/peak, duty cycle, ambient and cooling. Define power-off, reset, fault and full-storage behavior before drawing copper.
- [ ] **G1 — schematic and pin truth:** native KiCad schematic opens; ERC JSON contains no unexplained violations. Export native XML netlist. Compare normalized `(reference, pin, net)` membership against intended connectivity and board pads, including NC pins, exposed pads, connectors and repeated pad numbers. A matching wrong generator is not independent evidence: separately check every power semiconductor/driver/current-sense package against manufacturer pin tables and top/bottom-view land drawings. Record package suffix and pad dimensions. Multiple same-number pads on the same net may be intentional; unnamed paste apertures are not electrical pads.
- [ ] **G2 — BOM identity:** exact reference-set equality between schematic, PCB and population variant; one approved MPN/package/value per populated reference; explicit DNP and non-PCB items; quantities derived from reference lists, not hand counts. Confirm voltage, DC interruption, pulse, temperature and tolerance ratings from datasheets. Distributor stock is not a pinout authority. Include assembly side and CPL rotation/pin-1 review.
- [ ] **G3 — calculations and simulation:** reproducible scripts with units, sources, worst-case inputs and assertions. Sweep bus, speed, torque, temperature, component tolerance and faults. Save simulator version, netlist, model/license/version, convergence log, waveforms and numerical limits. Nominal plots alone do not pass. See power-specific requirements below.
- [ ] **G4 — placement before routing:** verify actual pad polygons, same-layer copper overlaps, pad numbers/net assignments, courtyard/body height, mounting, heatsink clearance, probe access and connector polarity. Opposite-face SMD pads overlapping only in XY are **not automatically shorted**; require shared copper layer, PTH/barrel, cutout or other physical conduction. Check through-hole intrusion and mechanical collisions separately. Do not import contrary blanket RF-board heuristics.
- [ ] **G5 — routed candidate:** refill zones; native DRC with violations-as-failure; zero shorts and zero unexplained unconnected items; inspect connected-component membership per net rather than only total counts. Check frozen clearance/track/via floors, layer stack, voltage-domain spacing, current paths and return continuity. No automatic relaxation of rules to obtain green. A DRC JSON `schematic_parity: []` without a loaded paired schematic proves no parity check.
- [ ] **G6 — power layout review:** annotate commutation, gate-drive and sense loops on each copper layer; measure loop geometry and Kelvin connections; inspect local ceramic/bulk capacitor placement, switch-node coupling, gate returns, shunt sense pickup and thermal bottlenecks. DRC cannot certify inductance, current capacity or thermal performance.
- [ ] **G7 — manufacturing packet:** export from the G5 hash; enumerate expected layers from actual stackup (not wildcard file count); check Gerber job, copper/mask/paste/silk/outline, plated/nonplated drill content, outline closure, dimensions, drill units and registration in an independent CAM viewer. Verify BOM/CPL reference equality and side/orientation; supplier confirms copper weight, stackup, slots, via-in-pad treatment and assembly capability. Record file hashes and archive manifest. Export exit zero is necessary, never sufficient.
- [ ] **G8 — visual and reproducibility:** top/bottom 2D, every copper layer and uncropped top/bottom 3D with scale, orientation and source hash. Declare missing 3D models. Inspect schematic readability and all power-path annotations. Rebuild twice in clean directories with pinned dependencies; compare normalized electrical/geometry outputs and explain any UUID/timestamp-only differences. Separately hash exact release outputs.
- [ ] **G9 — independent review and staged validation:** reviewer who did not author the generator checks datasheets, fault table, netlist, BOM and actual copper; resolve findings against frozen artifacts. Human signs the CAM preview and assembly plan. Before vehicle use: current-limited low-energy bring-up, gate waveforms/deadtime, fault injection, regenerative/full-storage tests and thermal load tests in a guarded bench setup. Keep independent mechanical brakes. No riding approval from simulation or DRC alone.

## Power-board additions (not transferable from a low-voltage RF board)

Sources below support the underlying device/layout behavior; the acceptance criteria are engineering requirements proposed here, not a claim of safety certification or a completed motor design.

1. **Hardware fail-safe and fault table.** For both bridges enumerate MCU unpowered/reset/hung, PWM disconnected or stuck, driver UVLO, shunt open/short, lost sensor, phase short, MOSFET short, battery/BMS opening and emergency stop. Specify truth tables, pull resistors, hardware inhibit/latch, comparator thresholds and detection-to-gate-off time. TI DRV835x [S2, protection and functional-mode sections] documents UVLO, overcurrent, gate-drive faults, deadtime and different retry modes; these are not a system safety guarantee. Check the actual selected device variant and register defaults. No fault may require healthy firmware to suppress unintended torque; distinguish torque disable from electrical isolation and from braking.
2. **Gate-off is not generation-off.** A spinning permanent-magnet machine can rectify through bridge MOSFET body diodes into the bus with every gate off. Draw diode current paths for both bridges, each rotation direction and battery disconnected. Analyze overspeed/back-EMF and all storage-full cases. S2's bridge topology and S1's freewheeling/current-path discussion underpin this circuit analysis. A BMS disconnect can remove the sink while energy is still arriving. Provide a rated energy destination or demonstrably safe isolation strategy; do not assume disabling PWM or opening a battery contactor clamps the DC bus.
3. **Full storage and bus overvoltage.** Budget incoming rider/generator plus wheel regenerative energy, winding energy and kinetic energy. For capacitance, available absorption is `0.5*C*(V_limit^2 - V_start^2)`, using minimum effective capacitance at bias/temperature. At full storage there may be essentially no charge acceptance. Validate chopper/dump resistance, switch SOA, resistor pulse energy and continuous descent power, threshold tolerances, response delay and failure states. Include wiring inductance `L*di/dt`, ringing, clamp dynamic resistance and parasitic capacitance. A TVS is not automatically a continuous brake resistor. S2 §10.1 explicitly makes bulk-cap sizing dependent on supply and motor behavior; S1 §6.3 explains overshoot from parasitic inductance.
4. **Switching loop and Kelvin layout.** S1 §§5–7: put local bypass capacitance at the power stage, minimize high-current commutation loops and gate-drive loop inductance, separate sensitive analog returns from switching current and route sense inputs as Kelvin pairs from the shunt terminals. Review each of the two bridges and their common bus coupling. Do not copy RF matching constraints or thin flight-board copper rules as motor current rules.
5. **Phase current is not bus current.** During PWM recirculation, substantial winding/MOSFET current can persist while battery current is small; size MOSFETs, shunts, copper, connectors and protection from phase RMS/peak waveforms. Compute DC-link capacitor ripple current independently. For each operating point show average bus power and phase loss, not `P_bus/V_bus` as a substitute for phase current. S2's current-sense and PWM-mode descriptions and S1's current-path diagrams are the relevant physical basis.
6. **DC ratings and tolerance/thermal margins.** Check selected fuse/contact/connector datasheets for DC voltage, prospective interruption current, polarity, hot-plug and derating; an AC marking cannot be substituted. Check every bus-facing pin, regulator, capacitor and MOSFET against normal plus transient stress, not the headline voltage on a driver product page. S2 distinguishes VM, VDRAIN and optional buck operating limits despite the “100-V” title. Use hot `R_DS(on)`, switching energy, reverse recovery, gate charge, shunt tolerance/TCR, amplifier offset/common-mode limits, ripple heating and realistic enclosure thermal impedance. S1 §2 describes PCB thermal paths; S2 absolute maximum/operating/thermal tables are distinct limits.
7. **Simulation limitations.** Ideal-switch and averaged models establish energy/control behavior, not shoot-through, avalanche, EMC or layout parasitics. Device models may omit fault behavior, reverse conduction or temperature dependencies. Require a model-capability ledger and worst-case parasitic sweeps; disclose missing motor R/L/back-EMF/inertia measurements. Hardware waveform and temperature correlation remains a release gate, with differential probes and equipment rated for the switching environment.

## Smallest tooling to port later

Do not import the balloon routing framework wholesale. Implement only after the circuit artifact names are settled:

1. `check_native_reports.py`: fresh reports, strict JSON schema/required keys, subprocess failure propagation, zero-error/unconnected policy and explicit waivers. Tests: missing CLI/report, stale report, malformed JSON, planted short and planted open must fail.
2. `check_net_bom.py`: normalized reference/pin/net and BOM/PCB/population set equality; explicit pad alias and NC maps. Tests: swapped MOSFET gate/source, missing shunt Kelvin pin, wrong package, omitted/DNP reference and duplicate ref.
3. `check_release_manifest.py`: input/output hashes, actual stackup-derived file inventory, BOM/CPL equality, rules hash, tool versions and verdict binding. Tests: omitted inner copper/drill file, wrong board hash, stale report, extra placement and changed rule file.
4. Reuse the **idea** of deterministic UUIDs from balloon `schematic_lib.py`; write a small native CLI wrapper rather than copying host paths, RF symbols or SKiDL netlist generation as if it were a readable schematic. Compare two builds before claiming reproducibility.

A simple shell entry point can sequence these three scripts and native KiCad commands. No new plugin system, router migration, gate dashboard or framework is required to finish the board.
